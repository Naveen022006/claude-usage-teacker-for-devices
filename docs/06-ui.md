# 06 — UI

## Widget (primary UI, injected on claude.ai)

### Sidebar panel (default placement)
`src/widget/anchor.ts` finds the left sidebar and inserts the panel as a sibling right after one row
(never inside React-owned nodes; if React removes it, it is re-inserted):
- **Chat** (any path not starting with `/code`): directly below the **Customize** row (`a[href*="/customize"]`, else a row whose
  text is "Customize", else a language-tolerant fallback: the last nav row before the first section heading), above "Pinned".
- **Claude Code** (`/code...`): directly below the **More** row (a button/link with text "More"), above "Recents".
- Rows are located by climbing from the matching element to the highest ancestor whose text is still just that label.
- **Fallback**: if no anchor is found, or the anchor is hidden / narrower than 120 px (collapsed sidebar), the old floating
  pill/panel (below) is used. A `MutationObserver` (throttled to ~4 checks/s), `popstate`/Navigation events and a 2 s heartbeat
  re-run the placement, so route changes and re-renders move the host back; only one host (`data-claude-usage-host`) ever exists.
- Looks native and flat (no card, no border): the host inherits `font`/`color` from the sidebar; 13.5 px tabular-nums text, rows
  aligned with the sidebar rows' text edge. Each row = label ("Session (5h):", "Weekly:", "Weekly Opus:", "Weekly Sonnet:") in normal
  text colour, the percentage in accent blue (dark `#5aa9ff`, light `#1a6fd1`; amber >= 80 %, red >= 95 %, bar fill too) in a column
  starting at 45 % of the width, and a muted clock icon + countdown right-aligned; under it a 3 px rounded bar (track =
  `currentColor` at 12 %). Light/dark comes from the luminance of the sidebar text colour (`data-theme` on the host), not from
  `prefers-color-scheme`. Left/right inset = inset of the row's inner link inside its wrapper.
- Contents: header "Usage" (muted; clicking the text toggles collapse, state in `widgetUi.panelCollapsed`; collapsed shows only the
  Session row with its countdown) and a blue settings gear (`open-options`). Missing account usage: muted "Plan usage unavailable".
  Countdown has no seconds (`4h 55m`, `3d 0h`, `12m`, `<1m`, `now`) and is refreshed by one 30 s interval that only rewrites `.cd`
  text nodes, running only while the panel is attached and the tab is visible.
- Models section: muted "Models" sub-header with an inline switch `5h · Today · 7d` (text buttons, `aria-pressed`, active one bold +
  underlined), then one row per model in the same style: `Sonnet 5.5:`  `69%`  `≈6.1k tok` (prettyModel names; "≈" only for estimated
  sources; bar = share; largest-remainder rounding to 100 %, sorted desc; max 6 rows then "+N more"; empty = "No usage in this window").
- Device data: **chat** = this browser's local aggregates (shown with "≈"); **code** = combined `byModel` of the hub devices selected
  in options (`codeDeviceIds`; empty = auto: every hub device with source `claude-code` or `desktop`), exact. Hub not configured shows
  a muted row "Connect your Usage Hub in options to see Claude Code usage" + link (`open-options`).
- Data refresh every 30 s and on `state-changed`. Options lists hub devices through the `get-hub-devices` UiRequest.
- Preview: `dist/widget-preview.html?mode=chat|code|floating&theme=dark|light[&hub=off][&extra=1]` mounts into mock sidebars.

### Floating fallback
A closed-Shadow-DOM widget (`src/widget/widget.ts`), fixed bottom-right (right 16 px, bottom 88 px by
default; drag vertically to move, position remembered). Constructable stylesheet, system font, follows
`prefers-color-scheme`. Disable via "Show widget on claude.ai" in options (`showWidget`, applied live).
- **Collapsed pill** (44 px): mini ring + "5h 42%" (or "Usage" if unknown). Click to expand.
- **Panel** (340 px wide, max 70 vh, scrolls): header "Claude usage" + sync dot + settings gear + minimize (Esc also collapses).
  - Plan usage bars per account window (five_hour "Current session (5h)", seven_day "Weekly · all models",
    seven_day_opus/sonnet, others title-cased) with % and "resets in 2h 14m"; green <60, amber <85, red >=85.
    Empty: "Plan usage unavailable".
  - Tabs: Session (5h) · Today · 7 days (ARIA tablist, arrow keys).
  - Device cards: "This browser" (local aggregates, always available) then hub devices (own deviceId excluded)
    with source badge (Claude.ai / Claude Code / Desktop), "stale · seen 2h ago" when not fresh, a totals line
    ("≈" only for estimated sources) and per-model rows (name without "claude-", messages, tokens, bar). Collapsible.
  - Footer: "Updated 12s ago" and hub status; when no hub is configured: "Connect a Usage Hub to see Claude Code & Desktop" (opens options).
- Refresh: on expand, every 30 s while open, every 60 s collapsed, and immediately on the service worker's `state-changed` broadcast.
- Fails soft: errors are logged as `[claude-usage]` warnings; claude.ai requests are never touched.
- Manual visual check: `npm run build`, then open `dist/widget-preview.html` (stubbed chrome.* with fake state).

The popup below is kept as a secondary UI.

## How per-model limit usage is calculated
Claude only reports a total utilisation per window (5-hour session, weekly). To show how many percentage points
each model consumed, the extension keeps an attribution ledger (`limitLedger` in `chrome.storage.local`, pure logic in
`src/shared/attribution.ts`):

1. Every completed reply (and every positive change in a hub Claude Code/Desktop device's last-5h token total) becomes a
   pending contribution with a weight `(prompt + 5 x output tokens) x model factor` (Opus 5, Sonnet 1, Haiku 0.3, other 1).
2. The account usage is read again 4 s and 20 s after each reply, plus every 1-2 minutes while a claude.ai tab is open.
3. Each increase in a window's utilisation is split across the pending contributions by weight. An increase with no
   pending contribution (other devices, mobile, another browser) goes to **Other**. The first utilisation seen in a cycle
   (when tracking starts, or after the window resets) is also **Other**. If the server lowers the value, everything is scaled down proportionally.
4. Sum of models + Other always equals the current utilisation. The ledger resets itself when a window's reset time changes.

Limits: this is an estimate. Utilisation has integer % granularity, so small replies are lumped with the next
change; the account is shared across devices, so anything not seen by this browser or your hub lands in Other; the
weights only split a change between replies, they do not predict cost. Options > Diagnostics > "Reset model attribution" clears the ledger.
The widget has no settings gear any more; open Options from the extension's right-click menu (or the "Open options" link).
